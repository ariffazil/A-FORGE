## Failing Tests (the regression target)

### I1. SEP-2567 — `arif_init verifies actor` ❌
- **Symptom:** `arif_init(mode=light, actor_id="regression-I1", actor_signature=...)` returns `actor_verified=False`
- **Root cause:** Session bound (session_id present, prefix `SEAL-`), but `actor_verified` is not `True` for non-`arif` actor_ids
- **Note:** I5 PASSES with `actor_id="arif"` — so the auth machinery is wired for the canonical actor, not for arbitrary ids
- **Fix direction:** Either widen verification (any actor_id should verify if signature valid) or document the "arif-only" semantics explicitly

### I3. SEP-1303 — `anonymous call → REJECTION (not HOLD-with-anonymous)` ❌
- **Symptom:** `arif_observe(mode=vitals)` with no `_envelope` returns `verdict=SYUBHAH, actor_id="openclaw-anon"`
- **Root cause:** Anonymous calls are not rejected at protocol level — they get a downgraded verdict with anonymous actor_id
- **Why this matters:** The user explicitly stated: *"HOLD means 'I evaluated and the evidence was insufficient.' Rejection means 'I never should have evaluated at all.'"* — current behavior conflates these
- **Fix direction:** SEP-2260 enforcement — orphan/anonymous calls must return error/VOID, not HOLD-with-anonymous

### I4. SEP-2260 — `orphan (_envelope=null) → REJECTION` ❌
- **Symptom:** Explicit `_envelope: null` also gets `verdict=SYUBHAH`, not rejection
- **Root cause:** Same as I3 — null envelope is treated as "no envelope provided" → anonymous fallback, not rejection
- **Fix direction:** Distinguish `_envelope=null` (explicit null, anti-orphan) from absent envelope (which the system can't control)

### I2. SEP-1303 — `equations_used canonical on compute` ❌
- **Symptom:** `wealth_compute_npv` with `cash_flows=[-1000, 500, 500, 500], discount_rate=0.10` returns `verdict=None` (silent success) with **empty `equations_used`**
- **Response keys:** `['tool_name', 'tool_version', 'domain', 'result', 'result_type', 'epistemic_tag', 'claim_state', 'evidence_quality', 'execution_authorized', 'execution_authority', 'human_final_authority', 'requires_888_hold', 'source_attribution', 'computation_timestamp', 'missing_inputs']`
- **Note:** `epistemic_tag` and `source_attribution` are present — but the canonical `equations_used` is missing
- **Why this matters:** User's call: *"pick one canonical name — `equations_used`, or `method_provenance`, or whatever — and require it non-empty on every non-HOLD compute."* The current schema gives us multiple near-equivalent fields, none canonical
- **Fix direction:** Designate `equations_used` as canonical, require non-empty on non-HOLD compute, treat empty as F2 violation

### S1. Two-surface — `WEALTH no surface drift` ❌
- **Symptom:** 50 of 50 WEALTH tools in the registry are **unmarked** — no `canonical`, no `deprecated` flag
- **Sample:** `wealth_wisdom_evaluate`, `wealth_power_audit`, `wealth_capture_scan`, `wealth_compute_npv`, `wealth_compute_irr`
- **Why this matters:** The user identified: *"any agent, not just me, could hit the wrong surface and wrongly conclude a working organ is broken."* Without explicit canonical markers, agents cannot distinguish legacy from canonical tools
- **Fix direction:** Add `canonical: true|false` or `deprecated: true|false` to every tool manifest; the GEOX/WEALTH bridge surface should expose only canonical

### S2. Two-surface — `GEOX no surface drift` ❌
- **Symptom:** 13 of 13 GEOX tools on the bridge surface are unmarked
- **Sample:** `geox_surface_status`, `geox_claim`, `geox_evidence`, `geox_prospect`, `geox_tie_receipt`
- **Note:** GEOX has documented 35 canonical + 49 backward-compat aliases (per GEOX AGENTS.md), but neither set is tagged in the live registry response
- **Why this matters:** Per the user's prior note, GEOX has 131 backward-compat tools NOT in canonical surface — the surface itself is honest, but the registry response doesn't communicate this to agents
- **Fix direction:** Tag every GEOX tool with `canonical: true` (for the 35) or `deprecated: true` (for the 49 aliases + 47 additional)
