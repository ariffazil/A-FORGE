## 0. TL;DR

FLAME's success classifier at `flame_router.py:1133-1135` misclassifies
**caller-fault** (`reasoning_content` returned, `content` empty due to insufficient
`max_tokens`) as **model-fault** (`reasoning_no_final`). This increments
`consecutive_fails`, triggering auto-demote at threshold=3.

The cascade: every reasoning-capable model demotes → FLAME falls through to
OpenRouter :free (20rpm/50rpd shared, RM0-marginal).

**Two independent probes** confirmed root cause:
- 333-AGI direct probe (this session, ~14:43 UTC)
- ASI independent probe (~14:46 UTC, cross-organ validation)

Both found Groq/Gemini/SEA-LION healthy with direct curls; FLAME marked them demoted.

+                # BUG FIX (S5 2026-08-04): reasoning_content with empty content is

## 4. Recovery-loop gap (separate, not blocking)

Grep for `promote` / `recover` / `self_heal` in `flame_router.py` and `routing_table.py`
returned no explicit recovery code. Demotions appear to self-resolve only via the
`consecutive_fails = 0` reset on each successful call (line 650). If a tier is
permanently broken, no auto-recovery probes it. This is a future hardening item:

- Add `_recover_demoted_tiers()` method that bypasses the tier chain
